## Data Flow: Lua → MixHive

```
User writes Lua script:
  music.set_bpm{bpm=140}
  music.play_note{pitch=60, duration=0.25, time=0}
  mh.publish{title="Track", audio_path="/tmp/master.wav"}

        │
        ▼
LuaScriptManager.execute(code)
        │
        ├── SafeMusicApi methods → action dicts stored in _actions list
        │     e.g., {"type": "transport_set_bpm", "bpm": 140}
        │
        └── New: MixHiveLua methods → action dicts stored in _actions list
              e.g., {"type": "mixhive_publish", "title": "Track", ...}

        │
        ▼
Action Router (new in Phase 3):
  - For Lua actions: return as-is (consumed by frontend)
  - For MixHive actions: dispatch to HTTP proxy endpoint
        │
        ├── POST /api/mixes/publish  →  https://mixhive.app/api/mixes/publish
        ├── GET  /api/mixes/search   →  Supabase SDK query
        └── GET  /api/mixes/track    →  Supabase SDK query

        │
        ▼
MixHive.vercel.app / mixhive.app
        │
        ▼
Supabase: mixes table, storage buckets
```

## Action Dispatch System

### Lua Actions (Phase 0-4)
Generated by `SafeMusicApi` methods. Returned as-is to the caller:
```json
{"type": "note_on", "pitch": 60, "velocity": 100, "channel": 0, "time": 0.0}
```

### MixHive Actions (Phase 5+)
Generated by `MixHiveLua` methods. Dispatched by backend proxy:
```json
{"type": "mixhive_publish", "title": "...", "bpm": 140, ...}
```

The `mixhive` action type prefix triggers HTTP dispatch.

## Security Model

| Layer | Mechanism | Status |
|-------|-----------|--------|
| Lua Sandbox | Lupa with register_eval=False, register_builtins=False | ✅ Existing |
| API Whitelist | `_ALLOWED_READS` (22 entries), `_ALLOWED_TRACK_READS` (11) | ✅ Existing |
| Attribute Handlers | `_whitelist_getter`, `_whitelist_setter` | ✅ Existing |
| Memory Limit | `max_memory` parameter (default 1MB) | ✅ Existing |
| MixHive Auth | Supabase session token validation | 🔧 New |
| HTTP Proxy | Backend validates actions before forwarding | 🔧 New |
| Rate Limiting | Per-session action rate limits | 📅 Planned |

## Error Handling

```
Lua Script Error
  ├── Syntax error → Lupa.LuaSyntaxError → Return error dict
  ├── Runtime error → Lupa.LuaError → Return error dict
  ├── Whitelist block → AttributeError → Return error dict
  └── Memory limit → MemoryError → Reset runtime

MixHive API Error
  ├── Network error → Catch → Retry with backoff
  ├── Auth error (401) → Prompt re-auth
  ├── Rate limit (429) → Backoff + retry
  └── Server error (5xx) → Log + return failure
```

## Session Lifecycle

```
Session created → LuaScriptManager instantiated
  → Runtime created with Lupa + sandbox
  → Standard library pre-loaded into globals
  → MixHiveLua instance bound
  → Agent scripts discovered and registered

Session active → execute() called
  → Actions collected in _actions list
  → MixHive actions dispatched via HTTP proxy
  → Results returned to caller

Session reset → reset() called
  → Runtime destroyed
  → Fresh runtime created
  → State cleared

Session destroyed → remove_lua_manager()
  → Runtime garbage collected
  → All state freed
```
